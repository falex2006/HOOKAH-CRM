# Команда разработки Territory CRM

В репозитории закреплены 16 специализированных профилей. В активной задаче Codex ими координирует основной агент: он делегирует независимые проверки, интегрирует изменения, выполняет QA и сводит результат. Подробный рабочий регламент и границы автоматизации описаны в [`docs/AI_ORCHESTRATOR.md`](AI_ORCHESTRATOR.md). Профили находятся в `.codex/team/roles/`, машиночитаемая схема — в `.codex/team/team.json`.

## Состав

1. Продуктовый аналитик
2. Системный архитектор
3. Ведущий UX/UI дизайнер
4. Специалист responsive/Fold
5. Frontend инженер
6. Backend/API инженер
7. Инженер данных и миграций
8. Эксперт склада и производства
9. Эксперт финансов и кассы
10. QA инженер
11. Визуальный аудитор
12. Аудитор безопасности и приватности
13. Инженер производительности
14. Дебаггер и специалист по дефектам
15. Инженер качества кода и технического долга
16. Координатор релиза и GitHub

Сквозная ответственность API и интерфейса закреплена за системным архитектором как функция «Интегратор API–интерфейса» внутри этой роли. Он также является постоянным владельцем общего каркаса CRM: бокового меню и верхней панели. Архитектор отвечает за согласованность маршрутов, ролей, состояний и общей структуры; design lead отвечает за визуальную сторону, frontend — за реализацию, QA и code-health инженер — за независимую проверку. Это не отдельная дополнительная роль. Release-менеджер отвечает за выпускной контроль внутри команды, а координацию всей активной задачи выполняет основной Codex.

Ограничение текущего оркестратора — до трёх параллельных runtime-агентов. Это не уменьшает состав команды: координатор подключает нужные профили пакетами и не запускает конфликтующие области одновременно.

## Как запускается работа

Задача проходит последовательность из `docs/AI_TEAM_WORKFLOW.md`. Профили являются специализированными инструкциями; фактический запуск субагентов обеспечивает доступный runtime Codex, а при его отсутствии основной агент выполняет этапы последовательно. Каждый привлечённый профиль обязан вернуть проверяемый результат. Ни одна кнопка, API или миграция не считается готовой без полного пользовательского пути и повторной проверки после обновления.

Инженер качества кода подключается к каждой задаче, меняющей программный код: сначала фиксирует существующие проблемы и риски области, затем проверяет итоговый diff и результаты подходящих анализаторов после реализации. Он не превращает локальную правку в несогласованный массовый рефакторинг; исправления в продуктовых файлах передаются их владельцам.

## GitHub

Командные профили, правила и CI-контракт хранятся в этом репозитории и проверяются workflow `AI team contracts`. Они не получают секреты и не выполняют скрытые действия. Production-публикация выполняется только координатором после обязательного QA и согласования необратимых действий.
