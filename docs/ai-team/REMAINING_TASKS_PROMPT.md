## Оставшиеся задачи

### 1. Довести PostgreSQL-проверки миграций и восстановления

Работай исключительно с изолированным контейнером `territory-crm-postgres-qa` и базами без реальных данных.

- Чистый bootstrap, upgrade от 038 и replay ранее прошли на изолированном PostgreSQL 16.15. После восстановления Docker engine добавь настоящую failure-injection проверку через фактический shell runner: ошибка внутри файла должна откатить весь этот файл, остановить дальнейшие CRM/seed-этапы, а retry после устранения причины должен завершить повторное применение без потери старых данных. Отдельно проверь 041 с синтетическими дублирующимися открытыми сменами, явным тестовым исправлением и повтором. Контракт на `--single-transaction` сам по себе не считается runtime proof.
- На настоящем PostgreSQL дополни незакрытые сценарии: 039 — сверка/KPI и безопасное закрытие с переходным NULL-платежом; 041 — конкурентное открытие смены; 042 — частичные/полные и конкурентные оплаты через API, переплата, непроведённая поставка и межзаведенческий доступ к обновлению. Ограничения/replay уже покрыты текущими миграционными PG-скриптами.
- Добавь только необходимые повторяемые PG-runtime проверки, если существующие тесты не покрывают критичные случаи. Не редактируй уже применённые миграции без отдельного совместимого решения.
- Не называй мок/контракт настоящим DB E2E. Если конкретный сценарий не проверен, зафиксируй это явно.

### 4. Подтвердить сквозные бизнес-цепочки и матрицу ролей

Используй синтетическое тестовое заведение и отделяй настоящие PostgreSQL/браузерные проверки от моков.

- Склад: поставка → остаток и совместимые единицы → техкарта/премикс → продажа → ровно одно автосписание → зафиксированная себестоимость → валовая прибыль.
- Персонал: график → фактическое время → расчёт периода → утверждение → выплата → расход; проверь границы дат, пересечение периода, повтор выплаты и связь с финансами.
- Касса: открытие и начальный остаток → способы оплаты → ожидаемая сумма → пересчёт → расхождение → чек-лист и X/Z → безопасное закрытие.
- Финансы: выручка − себестоимость − зарплата − операционные расходы; закупка не должна второй раз уменьшать управленческую прибыль при продаже.
- Права: для каждой роли проверь боковую навигацию, видимость элементов, разрешённые/запрещённые действия и прямые API-маршруты. Скрытое кнопкой действие обязано быть запрещено сервером.
- Исправляй только подтверждённые сбои и не меняй спорные бизнес-правила без требования или достоверного основания.
