# Локальная проверка ролей

Проверка границы публичных файлов: `node scripts/local-static-boundary.mjs`. Она запускает отдельный локальный сервер с обязательной авторизацией без БД, проверяет отказ на служебные пути и завершает свой процесс. Дополнительно проверяются рабочие маршруты, ресурсы из HTML/JS/CSS и состав Dockerfile. Проверка включена в `local-acceptance.ps1`.

Пока CRM не переносится на VPS, проверки выполняются только локально. Запустите отдельный локальный процесс с обязательной авторизацией:

```powershell
$env:AUTH_REQUIRED = 'true'
$env:DEMO_ADMIN_PASSWORD = 'admin'
$env:DEMO_OWNER_PASSWORD = 'demo'
$env:STAFF_PASSPORT_KEY = 'local-test-key'
node server.js
```

В другом окне PowerShell выполните:

```powershell
pwsh ./smoke-auth-required.ps1 -BaseUrl http://localhost:3000 -OwnerPassword demo -AdminPassword admin
```

Сценарий создаёт временные учётные записи и проверяет:

- доступ владельца и управляющего;
- запрет финансов и склада рядовому бармену;
- права старшего бармена и старшего кальянщика;
- режим разработчика с просмотром финансов и склада без права изменения;
- создание сотрудников и назначение допустимых ролей;
- несколько телефонов, Telegram, кадровые и паспортные данные;
- блокировку и восстановление сотрудника;
- отзыв сессии через `/api/logout` и возврат `401` после выхода.

После проверки тестовые записи существуют только в локальном процессе и не являются данными production.

Обычная локальная приёмка (`pwsh ./scripts/local-acceptance.ps1 -BaseUrl http://localhost:3000`) дополнительно запускает CRUD-контракт: товар с изображением, изменение и удаление категории, складское движение, финансовую категорию, бронирование с отменой и доставку со сменой статуса.
