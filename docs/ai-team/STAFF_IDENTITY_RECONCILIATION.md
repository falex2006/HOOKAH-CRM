# Проверка личности сотрудника и зависания рабочего места

Дата: 2026-10-01. Локальная ветка: `codex/local-reconcile-606800d`.

## Откуда появилась Мария

В старом `dist/index.html` основной рабочей папки имя `Мария` было записано прямо в `.user`. Это имя демонстрационного бармена, а не результат проверки входа. Исходный `index.html` уже исправлен, но опубликованная копия отставала: source подключал app rev170, dist — rev169. При задержке или зависании инициализации заглушка оставалась видимой.

Старая обработка ошибки `/api/session` дополнительно разрешала восстанавливать имя и права из `crm_session_user`. Поэтому устаревшая локальная личность могла отображаться даже без подтверждения сервера. Настоящий вход tenant-пользователя при настроенной PostgreSQL ищет его в `users`; demo account `staff` не является заменой для логина другого сотрудника.

Текущая публичная HTML-страница при отдельной read-only проверке уже содержала нейтральное имя. Достоверный ответ production `/api/session` в этом аудите не получен; вывод о записи Романа в production-БД не подменяется локальным тестом.

## Причина полного зависания

`staff-telegram-link.js` наблюдал все childList mutations в body и при каждом callback снова записывал `link.textContent`. Запись порождала следующую mutation. При наличии Telegram возникал бесконечный цикл microtasks. Аналогичная запись `innerHTML` в VIP deposit banner создавала тот же дефект для выбранного VIP-стола. Исправлены проверки перед изменением DOM; runtime QA подтверждает сходимость очереди.

## Локальное исправление

- Имя, роль и права рабочего места берутся из успешного `/api/session`. Ошибка не восстанавливает cached роль. 401 очищает локальную сессию и возвращает на вход; другие ошибки показывают повторную проверку.
- Профиль и Telegram загружаются после записи подтверждённого пользователя. Старый кеш не рисует аватар/контакты в состоянии проверки.
- Начальная разметка нейтральна: нет Марии, фиктивного заказа, занятого стола, открытой смены и демонстрационных счётчиков. Панель заказа inert до проверки сессии; смена заблокирована до чтения своего состояния.
- CSS `display:flex` ранее перебивал стандартное скрытие `button[hidden]`. Добавлен scoped hidden rule для меню сотрудника; запрещённые пункты теперь визуально скрываются.
- Таймаут чтения API — 8 секунд с отменой и понятным повтором. Сохранение не отменяется и не отправляется повторно по таймауту, поскольку отмена клиента не доказывает отсутствие записи на сервере.
- Маршруты сохраняют разрешённый venue/workspace контекст. Убраны старые inline fallback и переключение роли через mode/operator.
- Source/dist синхронизированы; app171, CSS365, staff-profile6, Telegram2, VIP3. Sync script копирует изменённые observer modules.
