# Статус проверки CRM «Территория» — 27.09.2026

## Актуализация 28.09.2026 — права при создании гостя и повторный Docker QA

При повторной проверке ролей найдена лазейка: пользователь с доступом только к заказам мог передать группу скидок, бонусный баланс или депозит прямо в запросе создания гостя. Теперь поля лояльности при создании, как и при редактировании, требуют права финансов, управления персоналом или лояльности. Проверка в настоящей временной PostgreSQL QA-базе подтвердила отказ `403` и отсутствие созданной записи. Обычное создание карточки гостя сохраняет прежний контракт.

После подтверждения готовности Docker выполнены все 10 PostgreSQL QA suites и полный локальный acceptance — оба набора прошли. Проверены миграции, закупки/оплаты, склад, рецептуры и списание, COGS/прибыль/денежный поток, сотрудники/зарплата, роли, касса и закрытие смены. Тестовые данные были синтетическими; контейнер удалён. Изменений БД, миграций, VPS и production не было.

Свежий браузерный и Fold-визуальный QA по-прежнему не подтверждён: Browser Use отклонил локальный preview URL по политике адреса. Его нельзя подменять статическим контрактом. В отдельном статическом обзоре дополнительно отмечены: отсутствие восстановления скрытых категорий финансов, посторонний блок правил на странице категорий, несовпадающее с картой сайта название настроек залов и устаревшая подпись правила страницы. Эти UX-находки ещё не исправлены и требуют следующего пакета.

Это свежая проверка геометрии и выборочных кадров, но не полный скриншотный просмотр каждой страницы при семи размерах. При переходе на старом preview-сеансе часть данных смены/аудита показывалась как недоступная; прямые API-запросы к тому же in-memory серверу отвечали 200, поэтому состояние отнесено к браузерной сессии preview и не выдано за production-дефект.

Во время текущего визуального обхода обнаружен `ReferenceError: getSettingsHashTarget is not defined` при последующем hash-переходе в настройках. Причина — helper был объявлен внутри соседней ветки условия, но использовался обработчиком `hashchange` вне этой области видимости. Объявление перенесено в общий scope `renderDashboard`, поднята версия portal до `290`, обновлён `admin-section-heading-contract.mjs`. Последующая проверка кода выявила второй связанный дефект: обработчик `hashchange` регистрировался заново при каждом рендере. Теперь он заменяет предыдущий listener на shell-элементе, а контракт проверяет отсутствие накопления обработчиков. Статический контракт, source/dist parity и полный local acceptance прошли до этой последней правки; после неё прошли синтаксис, целевой контракт и `git diff --check`. Browser runtime-повтор нескольких последовательных переходов после исправления всё ещё не завершён: вкладка локального preview недоступна для Browser Use, поэтому пункт остаётся требующим повторной визуальной приёмки.

Изменения текущего набора затрагивают shell и адаптивные стили, проверки навигации/шапки/склада и несколько QA-адаптеров. Бизнес API и SQL-схема этим набором не изменялись; новых миграций нет. Попытка пересобрать QA Docker-образ в самом конце остановилась на исчерпании памяти локального Docker credential helper при загрузке метаданных базового образа. Предыдущий полный запуск девяти PostgreSQL suites прошёл до этой попытки; по сохранённому выводу нельзя подтвердить, что он включал последние незакоммиченные изменения concurrency-тестов оплат поставщика. Поэтому PG baseline прошёл, но новые concurrency assertions остаются непроверенными в этом состоянии.

VPS и production по-прежнему не проверялись и не менялись. Домен/HTTPS, COOKIE_SECURE и security gates не изменялись.

Этот документ заменяет прежний отчёт с неподтверждёнными утверждениями о текущем production E2E и неверной нумерацией исходного ТЗ. - Добавлены миграции `039_shift_kpi_attribution.sql`, `040_payroll_lifecycle.sql`, `041_single_open_shift.sql`, `042_purchase_payment_link.sql`. Они проходили изолированный PostgreSQL bootstrap/upgrade/replay; на production здесь не применялись.
- Исправлена ошибка формы входа: ранее любой HTTP-отказ API мог использовать статическую демо-личность, в том числе при `session_limit_reached`, после чего сервер отклонял неподписанный/неизвестный токен. Теперь серверные ответы остаются на странице входа с понятным сообщением; статический demo fallback ограничен ситуацией, когда fetch не получил HTTP-ответ. Добавлены 401/409/network runtime-сценарии, опубликованный `login.js` синхронизирован, cache revision повышена.
- `migrate-vps.sh` изменён: каждый SQL migration file выполняется в `psql --single-transaction`, а `LC_ALL=C` задаёт стабильный порядок, совпадающий с Node runner. `scripts/migrate-vps-runner-qa.sh` проверяет shell-flow на fake Docker/psql, а `scripts/migrate-vps-postgres-qa.sh` дополнительно прошёл injected SQL failure, настоящий rollback и успешный retry на PostgreSQL 16.15.
- Затронутые группы API включают смены и их KPI, закрытие/оплату заказов, рабочее время и расписание, жизненный цикл payroll, документы закупок/платежи, расходы, права финансовых чтений, склад/техкарты и навигационные данные. Список маршрутов и фактический payload следует сверять с `API.md` и соответствующими обработчиками; эта сводка не заявляет browser E2E каждого endpoint.
- В предыдущей итерации исправлены конверсия координат редактора зала, перенос валюты KPI и timezone-конверсия PostgreSQL `DATE` в истории платежа поставщику. В этой итерации исправлено позиционирование hash-навигации: прямой переход в подраздел админки и переход по hash прокручивают к заголовку страницы, сохраняя видимыми H1 и основное действие вместо обрезания начала экрана. Source/dist синхронизированы; CSS revision 289, app revision 130, portal revision 284.
- `npm run qa:postgres` требует явно заданный `MIGRATIONS_PG_TEST_DATABASE_URL` с именем тестовой/QA/scratch БД и последовательно запускает 8 изолированных suite.
- Полный acceptance на временном сервере `127.0.0.1:3119`, `API_RATE_LIMIT=5000` прошёл после изменений. Все 8 suites `npm run qa:postgres` на тестовой PostgreSQL 16.15 прошли. Браузерная проверка исправленного hash-перехода подтвердила видимые заголовок и действие на `/admin#tasks` и `/admin#staff` в доступном узком окне; полный screenshot matrix не выполнен.
