# Команда разработки Territory CRM

В репозитории закреплены 15 специализированных профилей. Они работают как одна команда через координатора релиза: сначала общий диагноз, затем архитектурное решение, затем реализация, QA и повторная проверка. Профили находятся в `.codex/team/roles/`, машиночитаемая схема — в `.codex/team/team.json`.

## Состав

1. Продуктовый аналитик
2. Системный архитектор
3. Ведущий UX/UI дизайнер
4. Специалист responsive/Fold
5. Frontend инженер
6. Backend/API инженер
7. Инженер данных и миграций
8. Эксперт склада и производства
9. Эксперт финансов и кассы
10. QA инженер
11. Визуальный аудитор
12. Аудитор безопасности и приватности
13. Инженер производительности
14. Дебаггер и специалист по дефектам
15. Координатор релиза и GitHub

Ограничение текущего оркестратора — до трёх параллельных runtime-агентов. Это не уменьшает состав команды: координатор подключает нужные профили пакетами и не запускает конфликтующие области одновременно.

## Как запускается работа

Задача проходит последовательность из `docs/AI_TEAM_WORKFLOW.md`. Каждый профиль обязан вернуть проверяемый результат. Ни одна кнопка, API или миграция не считается готовой без полного пользовательского пути и повторной проверки после обновления.

## GitHub

Командные профили, правила и CI-контракт хранятся в этом репозитории и проверяются workflow `AI team contracts`. Они не получают секреты и не выполняют скрытые действия. Production-публикация выполняется только координатором после обязательного QA и согласования необратимых действий.
