# Безопасность перед боевым запуском

- Не хранить пароли и PIN в репозитории; использовать Argon2id/bcrypt и секреты окружения.
- Сессии выдаются через HttpOnly/SameSite cookie с истечением 8 часов; bearer поддержан для API-клиента. На VPS с HTTPS включать `COOKIE_SECURE=true`, чтобы cookie передавалась только по TLS.
- В текущем demo-режиме вход выдаёт bearer-токен в памяти (`owner`/`staff`, пароль `demo` без `.env`); перед VPS-релизом включить `AUTH_REQUIRED=true`, заменить demo-пароли и перенести пользователей/сессии в PostgreSQL.
- Чувствительные API-маршруты проверяют роль и разрешение на сервере.
- Скидки, возвраты, оплаты, разделение заказа и списания требуют аудита.
- PostgreSQL не публиковать наружу; доступ только из внутренней Docker-сети.
- Nginx обслуживает HTTPS, ограничивает размер запросов и добавляет security headers.
- Регулярные резервные копии PostgreSQL и проверка восстановления.
- Интеграции ККТ/ЕГАИС/«Честный знак» включаются отдельными флагами и имеют очередь повторной доставки.
- Логи не должны содержать PIN, пароли, токены и полные платёжные реквизиты.
