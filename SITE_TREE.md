# Дерево сайта Territory CRM

Подробная карта с ролями и связями разделов хранится в [SITE_MAP.md](SITE_MAP.md), а машиночитаемый источник маршрутов — в [site-map.json](site-map.json).

Публичный адрес каждой страницы один. HTML-файлы лежат в корне приложения как внутренние шаблоны, но пользователю доступны только канонические маршруты.

| Канонический адрес | Внутренний файл | Назначение |
|---|---|---|
| `/` | `index.html` | Главная рабочая панель: зал, заказы и режим сотрудника |
| `/login` | `login.html` | Вход и первичная настройка владельца |
| `/admin` | `admin.html` | Панель администратора |
| `/orders` | `orders.html` | Журнал заказов |
| `/clients` | `clients.html` | Гости и программа лояльности |
| `/reservations` | `reservations.html` | Бронирования |
| `/delivery` | `delivery.html` | Доставка |
| `/inventory` | `inventory.html` | Склад и связанные представления меню, техкарт и запасов |
| `/finance` | `finance.html` | Финансы и аналитика |
| `/finance/categories` | `finance-categories.html` | Категории расходов |
| `/finance/report` | `finance-report.html` | Финансовый отчёт |
| `/integrations` | `integrations.html` | Интеграции |
| `/network` | `network.html` | Сеть заведений |
| `/platform` | `platform.html` | Управление тарифом и организациями |

`/admin` не является заменой `/`: это отдельный административный режим. Возврат из него выполняется на `/` с сохранением выбранного рабочего режима только через query-параметр `mode`. Прямые адреса `/index.html`, `/admin.html` и остальные HTML-имена возвращают постоянный редирект 308 на канонический маршрут.

Вложенные маршруты со завершающим слешем (`/orders/`, `/inventory/` и т. п.) также получают 308 на slashless-вариант через Nginx; корневой адрес `/` сохраняется без изменений.

API находится только под `/api/*` и не смешивается со страницами. Статические ресурсы (`app.js`, `portal.js`, `header-shell.js`, `lock.js`, `style.css`, изображения и шрифты) не являются страницами и не добавляются в навигационное дерево. Все административные маршруты используют общий `header-shell.js`; рабочая панель сотрудника сохраняет отдельную операционную шапку.

У `/inventory` есть сохраняемые представления одной страницы: `?view=products` — каталог товаров, `?view=recipes` — технологические карты, `?view=stock` — остатки, `?view=auto-orders` — пополнение запасов, `?view=movements` — поставки и списания, `?view=premixes` — выпуск заготовок и премиксов, `?view=directories` — цеха и категории. Без параметра `view` открываются остатки. Эти значения синхронизированы с раскрываемыми группами «Меню» и «Склад»: производство премикса учитывает складские остатки и поэтому находится в группе «Склад».

Для статической публикации `dist/` использует ту же схему: у каждого канонического раздела есть собственный каталог с `index.html` (`dist/admin/index.html`, `dist/finance/index.html`, `dist/finance/categories/index.html` и т. д.). Эти файлы синхронизируются с корневыми шаблонами перед публикацией, поэтому Sites не получает старую копию страницы.
