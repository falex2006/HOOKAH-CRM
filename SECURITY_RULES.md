# Правила безопасности CRM «Территория»

## Доступ и сессии

- Владелец является администратором организации; права проверяются на сервере для каждого API-маршрута.
- Рабочий режим хранится отдельно от сессии. Выход из аккаунта не используется как механизм автоблокировки экрана: для паузы применяется PIN.
- На одного сотрудника разрешены максимум два активных устройства; токены хранятся в HttpOnly cookie и не сохраняются в браузерном автозаполнении CRM.
- Неуспешные входы ограничиваются: пять ошибок за минуту блокируют попытки на 60 секунд.

## Защита API

- Все API-запросы ограничены 180 запросами с одного IP за минуту; превышение возвращает `429` и `Retry-After`.
- JSON-тело запроса ограничено 2 MiB; превышение возвращает `413`.
- Запросы с изменением данных проходят проверку роли, разрешения, принадлежности к организации и смены.
- Рабочие операции сотрудников блокируются при отсутствии открытой смены.
- Закрытие смены требует подтверждения чек-листа, фактической кассы и сохраняет ожидаемую сумму и расхождение.
- Сервер возвращает `X-Content-Type-Options`, `X-Frame-Options`, строгий `Referrer-Policy` и CSP для API-ответов.

## Антифрод и аудит

- Переходы статусов заказов проверяются по разрешённому графу; повторное закрытие и переплата отклоняются.
- Скидки сотрудников оформляются заявкой с причиной и подтверждением владельца/администратора.
- Изменения смен, заказов, платежей, склада и прав записываются в журнал аудита.
- Секреты, PIN и паспортные данные не выводятся в клиентские логи и не передаются в открытом виде.

## Правило релиза

Перед публикацией запускать синтаксические проверки, API smoke-тест, проверку миграций и ручной сценарий для владельца, администратора и сотрудника. Любое изменение прав проверять минимум в двух ролях и на пустой базе.
