# Гигиена кода и технический долг

Инженер качества кода проверяет каждую программную правку на исходные риски и новые дефекты, а также участвует в итоговом review перед выпуском. Этот раздел хранит только подтверждённые замечания, требующие отдельного владельца или плановой работы.

## Правила учёта

- Сначала искать первопричину и воспроизводимый пример; не регистрировать предположения как дефекты.
- Указывать приоритет, затронутый модуль/файлы, проверку, владельца и минимальный безопасный следующий шаг.
- Отделять новые регрессии от технического долга, который существовал до текущей задачи.
- Не запускать массовые автофиксы и обновления зависимостей без отдельной проверки совместимости.
- Закрывать запись только после повторной проверки и указывать коммит или пакет, в котором исправление принято.
- Не сохранять секреты, токены, PIN-коды и персональные данные в этом реестре.

## Реестр

Подтверждённых замечаний в этом реестре пока нет. Это означает только, что аудит ещё не зарегистрировал их здесь, а не то, что весь код проекта без дефектов.
