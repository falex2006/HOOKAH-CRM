# Статус проверки CRM «Территория» — 27.09.2026

Этот документ заменяет прежний отчёт с неподтверждёнными утверждениями о текущем production E2E и неверной нумерацией исходного ТЗ. Таблица ниже сохраняет исходные номера и отдельный статус для каждого из 34 требований. `Частично` означает, что часть логики есть в коде и имеются ограниченные локальные проверки, но требуемая полная цепочка, роль, экран или production-среда ещё не доказаны.

## Проверенная среда и границы доказательств

- Репозиторий `main`, проверенная база commit: `b27546b472b63ad90dc5ce7fee98e3566f6e3e50` (`Complete integrated CRM QA and hardening`). На момент этого аудита изменения отчётности/мигратора ещё не закоммичены.
- Полный локальный `scripts/local-acceptance.ps1 -BaseUrl http://127.0.0.1:3116` прошёл на изолированном in-memory сервере с тестовым лимитом API. Он включает контракты, тестовые API-сценарии, mock-репозитории и smoke-проверки; сам по себе не доказывает production или полную PostgreSQL E2E-цепочку.
- На изолированном PostgreSQL 16.15 ранее прошли bootstrap `schema.sql` + 42 миграции, replay, upgrade synthetic-схемы 001–038 до 039–042 с сохранением старых записей и runtime-проверки триггеров/ограничений. Данные тестов откатывались. Это не покрывает параллельные API-запросы и все бизнес-цепочки.
- После последнего коммита Docker Desktop engine сейчас недоступен через `desktop-linux` named pipe. Повторный PostgreSQL/container run в этой итерации не выполнен.
- Последняя ограниченная browser-проверка sidebar и редактора гостей: Playwright-flow на 1280×… и 390 px; она не является проходом по всем маршрутам и состояниям.
- VPS и production в этой итерации не открывались и не менялись; актуальная версия production не проверена. Домен и HTTPS не входят в текущую проверку. `COOKIE_SECURE` и security gates не ослаблялись.
- Перед релизом остаются отдельная проверка всех 14 канонических маршрутов, 11 hash-подразделов администратора, всех ролей и ширин; полноценные PostgreSQL/API race-тесты; визуальные скриншоты каждой требуемой страницы/состояния; целевая проверка backup/deploy и post-deploy acceptance после сообщения владельца о доступности VPS.

## Изменения и тесты на проверенном локальном этапе

- Основные модули: `server.js`, `db.js`, `payroll.js`, `purchase-document-validation.js`, `portal.js`, `app.js`, `login.js`, `staff-profile.js`, `staff-admin-card.js`, `style.css`, HTML-маршруты и синхронизированный `dist/**`.
- Добавлены миграции `039_shift_kpi_attribution.sql`, `040_payroll_lifecycle.sql`, `041_single_open_shift.sql`, `042_purchase_payment_link.sql`. Они проходили изолированный PostgreSQL bootstrap/upgrade/replay; на production здесь не применялись.
- Исправлена ошибка формы входа: ранее любой HTTP-отказ API мог использовать статическую демо-личность, в том числе при `session_limit_reached`, после чего сервер отклонял неподписанный/неизвестный токен. Теперь серверные ответы остаются на странице входа с понятным сообщением; статический demo fallback ограничен ситуацией, когда fetch не получил HTTP-ответ. Добавлены 401/409/network runtime-сценарии, опубликованный `login.js` синхронизирован, cache revision повышена.
- `migrate-vps.sh` изменён: каждый SQL migration file выполняется в `psql --single-transaction`, а `LC_ALL=C` задаёт стабильный порядок, совпадающий с Node runner. Deploy contract проверяет эти условия. Failure injection/retry через фактический shell runner на PostgreSQL ещё не выполнен.
- Затронутые группы API включают смены и их KPI, закрытие/оплату заказов, рабочее время и расписание, жизненный цикл payroll, документы закупок/платежи, расходы, права финансовых чтений, склад/техкарты и навигационные данные. Список маршрутов и фактический payload следует сверять с `API.md` и соответствующими обработчиками; эта сводка не заявляет browser E2E каждого endpoint.
- Профильные контракты проходят после этих изменений: 34-row matrix contract, login 30-check contract/runtime QA, migration contract (42 файла), deploy contract, local design contract; полный acceptance повторно пройден на временном локальном in-memory сервере на порту 3117 с `API_RATE_LIMIT=5000`. Smoke тест сообщил, что тестовая in-memory смена уже открыта от предыдущего сценария, поэтому переход open/close был осознанно пропущен самим smoke-тестом.
