# Следующий этап: CRM QA и закрытие функциональных пробелов

Работать в существующем проекте и не создавать новый сайт.

1. Последовательно открыть локально все маршруты: обзор, заказы, гости, бронирования, доставка, рабочее место, склад, финансы, отчёты, интеграции и персонал.
2. На каждой странице проверить визуально desktop/tablet/mobile: нет горизонтального скролла, элементы не обрезаны, отступы единообразны, кнопки и пустые состояния читаемы.
3. Нажать каждую видимую кнопку и открыть каждую форму, меню, фильтр и модальное окно. Проверить успешные действия, отмену, ошибки и возврат назад.
4. Проверить роли: владелец, управляющий, старшие сотрудники, рядовой персонал и разработчик. Финансы, склад и кадровые данные должны скрываться по правам.
5. Проверить сквозной сценарий: смена → стол → заказ → товар → работа → гость → скидка-заявка → разделение → частичная оплата → закрытие → аудит.
6. При найденной проблеме исправить её в существующем коде и добавить соответствующую локальную проверку, если это возможно.
7. Не повторять уже подтверждённые этапы из docs/IMPLEMENTATION-STAGES.md.
8. После блока исправлений запустить локальный acceptance, записать результат и сделать один понятный Git-коммит.
9. VPS не трогать до полного завершения локального QA.
