# Hookah CRM

Веб-CRM для кальянной: рабочее место персонала, заказы, столы, бронирования, склад, финансы и административная аналитика.

## Сейчас реализовано

- рабочий экран персонала со статусами столов;
- серверный каталог товаров;
- создание заказов и добавление позиций через API;
- заявки на скидку и их согласование;
- разделение заказа;
- роли и разрешения;
- начальная PostgreSQL-схема и демо-данные;
- Docker Compose для CRM, PostgreSQL и Nginx.

## Запуск без Docker

```powershell
node server.js
```

Открыть `http://localhost:3000`.

Для локального demo-входа используются `owner` / `demo` и `staff` / `demo`. В VPS `.env` обязательно задать собственные `DEMO_*_PASSWORD` и оставить `AUTH_REQUIRED=true`.

## Запуск на VPS

```bash
cp .env.example .env
# изменить секреты в .env
docker compose up -d --build
```

Перед боевым запуском настроить DNS, HTTPS, резервные копии и секреты согласно `SECURITY.md`.
Для VPS использовать `deploy-vps.sh`, а для резервной копии PostgreSQL — `backup-postgres.sh`.

## Документация

- `ARCHITECTURE.md` — роли и бизнес-правила;
- `API.md` — контракт API;
- `schema.sql` — структура PostgreSQL;
- `seed.sql` — начальные данные;
- `ROADMAP.md` — этапы разработки;
- `DEPLOYMENT.md` — развёртывание;
- `SECURITY.md` — требования безопасности.

- feature flags будущих интеграций ЕГАИС, Честный знак, ККТ и ОФД (/api/integrations);
- воспроизводимая проверка smoke-test.ps1.

- /login — вход в CRM; / — рабочее место персонала; /admin — панель управления.

- MIGRATIONS.md — порядок подготовки PostgreSQL на VPS.

Разделы `/inventory`, `/finance`, `/reservations` доступны как отдельные административные страницы: они загружают остатки, финансовую сводку и бронирования через API и включены в образ.
- `db.js` — PostgreSQL-репозиторий заказов с fallback для demo-режима.
- `portal.js` — общий интерфейс административных страниц.
- Карточка компании позволяет менять телефон и логотип; владелец может добавлять сотрудников, загружать им аватары и деактивировать доступ.
- Каталог товаров поддерживает изображения карточек через `POST /api/products/:id/image`.
